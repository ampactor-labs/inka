# Mentl MN Design

## Required Reading

Before changing `.mn` code or syntax-facing docs, read:

1. `CLAUDE.md`
2. `docs/SYNTAX.md`
3. the local source files that define the construct being changed

Treat `docs/SYNTAX.md` as the syntax authority. If source and docs disagree, verify with artifacts before choosing a direction.

## Acceptance Bar

Do not accept `.mn` code merely because it compiles.

Check that it:

- carries truth through graph, effects, rows, ownership, lowering, and reasons
- uses the five topological operators where they express the shape better than ordinary call syntax
- keeps handlers and resumes as live-flow structure, not callback imitation
- preserves identity by names, node-kinds, rows, and reasons rather than by positions or incidental encoding
- makes Mentl more itself inside and out

## Design Pass

Use these interrogations before editing or approving a design:

- Graph: what node or edge owns the fact?
- Handler: which operation captures or resumes the flow?
- Verb: which topological operator is the natural surface?
- Row: what effect row is removed, added, opened, or closed?
- Ownership: what is borrowed, consumed, duplicated, or forbidden to escape?
- Refinement: what fact narrows the value, and where is it carried?
- Gradient: does this shape preserve differentiable or incremental structure?
- Reason: what explanation will the graph retain for diagnostics and tools?

## Syntax Discipline

- Prefer product-with-holes, named identity, and pipeline completion over positional shims.
- Prefer live graph reads over stale copied facts.
- Prefer a node-kind projection over inferring from runtime substrate bodies when the type belongs to the node-kind.
- Prefer structural equality and existing local helpers over bespoke comparators.
- Avoid importing Python, TypeScript, Rust, or Haskell idioms into `.mn` unless the Mentl form is explicit and documented.

## Writing

- Use plain, specific prose in docs, comments, commit messages, and examples.
- Remove LLM tells: generic praise, vague grandeur, filler transitions, and stock phrases.
- Do not add AI attribution, `Co-authored-by`, `Assisted-by`, or "generated by" language.
- Comments should protect invariants or explain a trap; delete comments that merely restate code.

## Verification

After changing compiler semantics or `.mn` language behavior:

1. Run focused micros or probes that hit the construct directly.
2. Run `bash tools/verify.sh`.
3. Run `bash tools/state.sh` when fixed-point or first-light state matters.
4. Commit generated seed artifacts with their semantic source change.
