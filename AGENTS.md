# Mentl Agent Contract

## Start Here

- Before changing `.mn`, compiler, bootstrap, syntax, or design files, read `CLAUDE.md`, `docs/SYNTAX.md`, and the relevant live artifacts. Treat `docs/SYNTAX.md` as the syntax authority.
- Prefer current artifacts over stale planning prose. Run `bash tools/state.sh` to establish ground truth when resuming bootstrap work.
- Use `rg` for search and WABT/wasmtime through `tools/wt-env.sh`; do not hand-roll feature flags.
- Keep `.mn` source, seed WAT, `bootstrap/mentl.wat`, and `bootstrap/mentl.wasm` aligned when a semantic bootstrap change requires it.
- Run `bash tools/verify.sh` before committing compiler, syntax, runtime, or seed changes unless the user explicitly asks for a narrower checkpoint.

## Mentl Code

- Verify alignment with `docs/SYNTAX.md` before deciding that any `.mn` code is acceptable.
- Prefer Mentl's five topological operators and live-flow design over host-language habits.
- Preserve carried truth through graph, effects, rows, ownership, lowering, and emitted artifacts.
- Design toward the system Mentl is meant to be. Do not patch around a bad encoding when the right move is to restore the underlying node-kind, handler, row, ownership, or reason structure.
- Use WABT tooling to pin traps and field offsets before speculating about runtime corruption.

## Writing Standard

- Do not add AI attribution, co-author trailers, `Assisted-by`, or "generated by" wording to commits, docs, code comments, or prose.
- Write like a careful human engineer: concrete, direct, and specific. Avoid empty hype, canned launch language, generic LLM phrasing, and self-congratulatory claims.
- Keep comments and docs useful to future maintainers. Explain invariants, traps, and design pressure; do not narrate obvious code.
- Commit messages should name the change and the invariant it protects. No marketing voice.

## Git

- Do not revert user changes unless explicitly asked.
- Keep unrelated scratch files, logs, probes, and WIP scaffolds out of commits.
- Prefer logical commits that preserve a useful history. Include generated seed artifacts with the source change that requires them.
